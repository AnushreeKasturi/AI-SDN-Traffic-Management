      How the controller decides

      Five stops, repeated for every new flow

      1. Read the network

        Poll flow statistics and per-port byte counters from every switch.

      2. Classify the flow

        A Random Forest labels it voice, video, web or bulk, which sets its priority.

      3. Forecast load

        A second model predicts each link's utilization for the next interval.

      4. Weigh every link

        Busy and soon-to-be-busy links get expensive, more so for voice and video.

      5. Install the path

        Dijkstra picks the cheapest path and the controller pushes OpenFlow rules hop by hop.

      cost = base delay + priority factor × (35 × current load³ + 12 × forecast load³)

      More learning did not mean better routing
      
            
      A class-aware Dijkstra profile, chosen on validation data, performed best. The Q-learning hybrids never significantly beat it on mean or voice/video latency, and the result held on NSFNET, a network it was never tuned on.

      Run it yourself
      Ubuntu or Debian with root access
      
          
      sudo apt-get install -y mininet openvswitch-switch iperf
pip install -r mininet_sdn/requirements.txt
cd mininet_sdn && python3 train_models.py
sudo ./run_demo.sh static      # baseline
sudo ./run_demo.sh adaptive    # AI-driven controller
